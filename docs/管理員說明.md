# channelcollab 管理員說明

管理員負責：幫每位成員建 Discord Bot、把 token 安全地交給本人、發佈與更新 plugin。名冊由每個人自己維護（第 4 節）。

成員端的操作見 `docs/企劃使用說明.md`。

---

## 1. 整體流程

```
管理員                                         成員
 /channelcollab:create-bot（幫成員建）
   → 建 Bot、存 token 成交付檔
   → 驗證設定、邀請 Bot 進伺服器
   → 把新 Bot 寫進自己的名冊，主人 ID 附進交付檔
 私下把交付檔交給成員 ──────────────────────→  /channelcollab:setup
                                                → 匯入交付檔（token、主人 ID）
                                                → 刪除交付檔
                                                → 綁頻道、啟動
 每個人自己維護名冊 ────────────────────────→  /channelcollab:roster
                                                （把常合作的人和 Bot 加進來，只要 Discord ID）
```

---

## 2. 建 Bot：`/channelcollab:create-bot`

在自己的 Claude Code 執行 `/channelcollab:create-bot`，選「管理員幫某位成員建」。skill 會帶你在 Developer Portal 完成建立（可以用瀏覽器自動化，也可以一步步手動），重點：

- Bot 建在 Developer Portal 的 **Team** 底下，方便日後統一管理。
- token 只經過剪貼簿，由腳本存檔；**token 不會出現在對話裡**。
- 幫成員建時，token 存成**交付檔** `<HOME>\handoff\<成員名稱>-bot.json`，不會寫進你自己的 `config.json`。
- 交付檔建立時帶 `--owner-id <成員的 Discord 使用者 ID>`，成員匯入後自動成為 Bot 的主人（只有主人能按權限按鈕）。
- 最後寫名冊時帶 `--handoff "<交付檔>"`：新 Bot 寫進**你自己的**名冊，主人 ID 和這個 Bot 自己那一筆附進交付檔（成員的 Bot 因此知道自己是誰）。你的整份名冊不會附進去。

`<HOME>` 是管理員自己的 channelcollab 資料夾，預設 `%USERPROFILE%\.channelcollab`（環境變數 `CHANNELCOLLAB_HOME` 可以改）。

---

## 3. 安全地交付交付檔

**交付檔裡是明文 Bot token。** 拿到 token 的人可以用這個 Bot 的身分在伺服器上發言、讀取它看得到的訊息。

- 只用**私下管道**交給本人：Discord 私訊、公司內部的一對一訊息、當面用隨身碟。**不要貼在任何頻道、群組、共用資料夾或文件裡**。
- 成員匯入後，請對方刪除檔案，用私訊傳的也刪掉那則訊息；**你自己這邊的 `handoff\` 檔案也刪掉**。
- 懷疑外流時：到 Developer Portal 該 Bot 的 **Bot** 頁籤按 **Reset Token**，舊 token 立刻失效。再用 create-bot 的 `save-token --for member` 重產交付檔交給本人。

## 4. 名冊（每個人自己維護）

名冊決定一個 Bot 認得哪些 Bot、哪些人。有兩種條目：**Bot**（ID、名稱，可選填主人與角色）和**成員** `members`（人的 ID、名字，可選填角色）。Bot 用它在提示詞中標示發話者，知道要交棒給某個 Bot、或要找某個人（例如企劃）時該 @ 誰。

- **名冊是每個人自己的**：每個 Bot 只讀自己 HOME 的 `<HOME>\roster.json`，沒有「正本」，管理員也不用發放。管理員的名冊就只是管理員自己 Bot 的名冊。
- 建 Bot 時，create-bot 的 `roster` 子命令把新 Bot 寫進**建立者自己的**名冊。其他人想讓自己的 Bot 認得這個新 Bot，就用 `/channelcollab:roster` 自己加。
- 加入只要 Discord ID，名字和是不是 Bot 會用自己 Bot 的 token 向 Discord 查（伺服器暱稱優先）：
  ```
  node "<plugin>/scripts/channelcollab.mjs" roster add <Discord ID> [--role planner] [--home <HOME>]
  node "<plugin>/scripts/channelcollab.mjs" roster remove <Discord ID>
  node "<plugin>/scripts/channelcollab.mjs" roster list
  ```
  查不到時（沒有 token、ID 不存在）會要求 `--name <名字>`，Bot 再加 `--bot`。
- 想一次給別人很多條目，可以把自己的 `roster.json` 傳給對方（名冊沒有 token），對方用 `roster import <檔案>` **合併**：新的 ID 加進來，同一個 ID 預設保留對方自己的（加 `--theirs` 才改用你的）。
- 改了名冊從下一個新對話開始生效，不用重啟 Bot。Bot 啟動時 log 會印 `[roster] N bots, M members from <路徑>`。
- **名冊不放在 plugin 或 repo 裡**（repo 是公開的，名冊有真實的 Discord ID）。plugin 只附假資料的 `roster.example.json` 當格式範例。

格式：

```json
{
  "version": 1,
  "bots": [
    {
      "botId": "Bot 的使用者 ID",
      "botName": "Bot 顯示名稱",
      "ownerName": "主人名稱（可省略）",
      "ownerDiscordId": "主人的 Discord 使用者 ID（可省略）",
      "role": "engineer 或 planner（可省略）"
    }
  ],
  "members": [
    {
      "discordId": "人的 Discord 使用者 ID",
      "name": "名字",
      "role": "engineer 或 planner（可省略）"
    }
  ]
}
```

`members` 可以省略（舊的名冊沒有這個欄位，照常運作）。

## 5. 發佈與更新 plugin

### marketplace 位置

plugin 透過 GitHub repo `jijia-Huang/channelcollab` 發佈。repo 根目錄的 `.claude-plugin/marketplace.json` 宣告了一個 plugin，原始碼在 `plugin/` 子資料夾。成員安裝：

```
claude plugin marketplace add jijia-Huang/channelcollab
claude plugin install channelcollab@channelcollab
```

測試時也可以用本機資料夾當 marketplace：`claude plugin marketplace add <repo 的本機路徑>`（本機路徑的 marketplace 直接讀資料夾裡的檔案，改了重開 Claude Code 就生效）。

### 發佈新版

1. 改好 `src/` 之後，在 repo 根目錄執行：
   ```
   npm install
   npm run build:plugin
   npm run test:plugin
   ```
   `build:plugin` 會把 `src/` 打包成 `plugin/runtime/bot.mjs`、`stop.mjs`，並產生釘死版本的 `package.json`、`package-lock.json`、`version.json`。**這些產物要提交進 repo**：成員從 git 安裝時拿到的就是這些檔案，不會在他們電腦上建置。
2. **把 `plugin/.claude-plugin/plugin.json` 的 `version` 加一**（例如 0.1.0 → 0.1.1），再跑一次 `npm run build:plugin`。Claude Code 用這個版本號判斷有沒有更新；**沒改版本號，成員就收不到更新**。
3. 提交並推送。
4. 通知成員更新：
   ```
   claude plugin marketplace update channelcollab
   claude plugin update channelcollab@channelcollab
   ```
   重開 Claude Code 後 `/channelcollab:stop`、`/channelcollab:start`，start 會偵測到執行環境有新版並自動重新安裝。

### 執行環境放在哪裡

plugin 的安裝資料夾每次更新都會換一個新的，舊的過一陣子會被清掉，所以 Bot 的執行環境不放在那裡：setup 把 `plugin/runtime/` 複製到成員的 `<HOME>\runtime\`，在那裡用 `npm ci --omit=dev` 裝固定版本的依賴（約 300 MB，主要是 Agent SDK 內建的 Claude Code 執行檔）。桌面的啟動／停止 `.bat` 也指向這份複本，plugin 更新不會讓它失效。

## 6. 一台電腦跑多個 Bot

每個 Bot 用一個自己的 HOME 資料夾。所有指令都可以加 `--home "<資料夾>"`，或先設環境變數 `CHANNELCOLLAB_HOME`。匯入交付檔時，如果目標 HOME 已經有另一個 Bot 的 token，腳本會停下來，不會覆蓋（確定要取代才加 `--replace`）。

`shortcut` 產生的 .bat 檔名帶 Bot 名稱（「啟動 <Bot 名稱>.bat」等；名稱取自名冊或最後一次登入的 Bot，也可以 `--name` 指定），所以好幾個 HOME 的捷徑放在同一個資料夾也不會互相覆蓋。同一個資料夾裡指向同一個 HOME 的舊檔名（0.1.5 的「啟動 channelcollab Bot.bat」等）會自動換掉；指向別的 HOME 的不動。建好的路徑記在 `<HOME>\launchers.json`，`status` 用它指出實際存在的檔案。

## 7. 疑難排解

| 狀況 | 處理 |
|---|---|
| 成員啟動時 401 | token 被 Reset 過或交付檔太舊。重產交付檔 |
| Bot 上線但收不到訊息內容 | Message Content Intent 沒開。用 create-bot 的 `verify` 檢查 |
| 成員說權限按鈕按了沒反應 | 確認按的人是主人：`/channelcollab:status` 看主人 ID 是否正確，不對就 `set-owner` |
| 成員的 Bot 不認得某個新 Bot 或某個人 | 那個 Bot／人不在對方的名冊裡。請對方 `/channelcollab:roster` 用 Discord ID 加進去 |
| 更新 plugin 後行為沒變 | 檢查是否改了 `plugin.json` 的 `version`；成員要 stop 再 start 才會換新的執行環境 |
| 有人在頻道 @ Bot 沒反應，log 有 `[ignore] ... not-allowed` | 白名單擋下了：請 Bot 的主人把對方加進名冊，或 `access --roster-only off` 關掉白名單 |
| 成員說點選單裡的 Bot 名稱 @ 它沒反應 | 0.1.5 起 @ 到 Bot 自動建立的同名身分組也算 @ 了 Bot；舊版要點使用者那一個 |
| 成員私訊 Bot 沒反應 | `status` 看私訊是否開啟、是否設了 PIN；log 有 `[ignore] ... dm-...` 會寫原因 |
| Bot 整隻不理人，log 有 `locked (wrong PINs)` | PIN 連錯 3 次被鎖定：主人在電腦上執行 `unlock`（或雙擊「解除 <Bot 名稱> 鎖定」，`status` 會指出實際的檔案），或重啟 Bot |
| 打 `/` 看不到 Bot 的斜線指令 | bot.log 找 `[commands] registered … global slash commands`；`registration failed` 時看原因。剛註冊要等一下或重開 Discord；仍沒有就用 create-bot 的 `invite` 網址重新邀請（不會踢掉 Bot） |
| `status` 的「最近的錯誤」出現 `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` | 0.1.6 起已過濾，也不再寫進 bot.err.log（reply 工具一律放行是刻意的設計）。看到的話是舊版留下的，stop 再 start 即可 |

## 8. 私訊、PIN、白名單、禁區（0.1.5）

### 設定欄位（`<HOME>\config.json`，只用總控腳本改）

| 欄位 | 預設 | 說明 |
|---|---|---|
| `dm` | 沒有（關閉） | 私訊設定，欄位和頻道綁定相同：`cwd`、`model`、`permission_mode`、`launcher`。`bind --dm --cwd <資料夾> [--permission-mode auto] [--launcher <路徑>] [--model sonnet]` 開啟，`bind --dm --remove` 關閉。不允許 `bypassPermissions` |
| `security.pin_unlock_minutes` | 30 | PIN 正確後多久內不用再輸入 |
| `access.roster_only` | true | 白名單：只有主人、名冊成員、名冊上 Bot 的主人、名冊上的 Bot 能叫 Bot。`access --roster-only off` 關閉 |
| `defaults.owner_wait_minutes` | 2 | 權限請求等主人多久（和 `permission_timeout_minutes` 取短的），之後改成「稍後核准」 |

- 私訊用的是 `DirectMessages` intent，不是特權 intent，Developer Portal 不用改設定。Bot 啟動時 log 會有 `[dm] intent DirectMessages on; …`。
- 私訊只有主人能用；別人私訊會收到「這隻 Bot 只接受主人私訊」（同一人 10 分鐘內只回一次）。沒開 `dm` 時回「私訊未開啟」。**沒設 PIN 時私訊一律不開放**。

### PIN

- `set-pin`／`clear-pin`／`unlock`（都支援 `--home`）。這三個指令一定要在電腦前的人自己操作：不是在主控台裡執行時（例如由 Claude Code 執行）會另開一個主控台視窗讓本人輸入。PIN 不經過命令列參數、shell 歷史或 Claude 的對話。
- `<HOME>\pin.json` 只存 scrypt 雜湊和 salt；Bot 每次驗證時重新讀檔，所以設定、移除都不用重啟。驗證用固定時間比對；輸入的內容不進 log、不進提示詞。
- 連錯 3 次（只算主人送出的；非主人按「允許」根本看不到 PIN 視窗）就鎖定：整隻 Bot 暫停，所有觸發都不理，在發生的頻道或私訊發一則提醒。`unlock`（經 Bot 的 named pipe）或重啟才解除。每個 HOME 各自計算、各自解鎖。
- 捷徑有「設定 <Bot 名稱> PIN.bat」「解除 <Bot 名稱> 鎖定.bat」（`shortcut` 產生；0.1.5 以前是固定檔名「設定 channelcollab PIN.bat」等）。

### 禁區

所有權限模式都有效，按鈕也解不開；在 PreToolUse hook 最前面判斷，比 auto 模式的自動判斷更早：

- channelcollab 的 HOME（自己的，以及任何 `.channelcollab*` 資料夾）——但這個對話自己的附件資料夾可以讀；
- `.ssh` 資料夾、`.env`／`.env.*` 檔、`.credentials.json`（Claude 的登入資料）；
- 指令裡執行 `channelcollab.mjs`、`create-bot.mjs`、`ctl.mjs`（改設定、PIN、白名單都要主人在電腦上自己做）。

讀寫檔案的工具（Read、Edit、Write、MultiEdit、NotebookEdit、Grep、Glob、LS）比對解析後的路徑，大小寫和斜線都正規化。Bash、PowerShell 和其他 MCP 工具只能比對指令文字，是**盡力而為**：用變數、編碼等方式組出路徑就比對不到。

### 稍後核准

主人 2 分鐘沒按權限按鈕時，那個動作排進待核准清單（存在 `state.json`，24 小時有效），Bot 私訊主人一張卡片（私訊送不出去就發在討論串），討論串只留一則短通知。主人允許後 Bot 自動接著做，只放行清單上參數完全相同的動作（比對方式同 auto 模式核准後重試，忽略 `description`）。

### 資安說明（給成員的完整版在企劃使用說明第 7 節）

- **風險**：頻道裡的人能叫 Bot（白名單只限縮到名冊）；auto 模式下讀檔和 reply 不經過主人；Bot 回覆的內容存在 Discord；token 等於 Bot 的帳密；檔案、網頁、訊息可能藏有提示注入。
- **防護**：Discord 兩步驟驗證、私人頻道、白名單、PIN、禁區。
- **帳號被盜時**：(1) 在那台電腦執行「停止」.bat 斷線；(2) 改 Discord 密碼並重設兩步驟驗證，檢查裝置和已授權的應用程式；(3) 到 Developer Portal 重設 Bot token，重產交付檔讓本人重新匯入；(4) 看 `bot.log`，並在各工作目錄跑 `git status`、`git log`；(5) 通報 IT。
- **限制**：Bot 看不到 IP 和裝置，只知道 Discord 帳號；PIN 的 Modal 輸入框沒有遮罩，輸入時注意旁人；禁區對指令只能盡力比對。

## 9. 只用私訊、斜線指令、/skill（0.1.6）

### 只用私訊

- config 只有 `dm`、沒有任何 `channels` 也能正常啟動（`discord.guild_id` 本來就是選填）。`status` 顯示「模式：只用私訊」，沒綁頻道不算問題；頻道和私訊都沒設定時才提示要設定。Bot 啟動時 log 有 `[mode] direct messages only (no channel bound)`。
- Discord 的限制：使用者和 Bot 至少要在同一個伺服器，才能私訊 Bot。只用私訊的人可以把 Bot 邀進自己建的私人伺服器。
- 成員自己建 Bot（create-bot 選「只給自己私訊用」）：token 直接存進自己的 HOME，邀請網址用 `invite --dm-only`（權限整數 0，scope 一樣是 `bot applications.commands`），不用經過管理員，也不寫名冊。私訊不受伺服器權限控制，所以權限可以是 0；之後要在那個伺服器綁頻道，再用一般網址重邀即可（不會踢掉 Bot）。
- 如果 config 設了 `discord.guild_id`，只有那個伺服器的頻道訊息會處理（私訊不受影響）。只用私訊的人之後在別的伺服器綁頻道時要注意這點。

### 斜線指令

- Bot 上線時用 bulk overwrite（PUT）註冊 global commands：`/help /clear /resume /stop /status /model /plan /compact /retry /skill`。冪等，重啟不會重複。log：`[commands] registered 10 global slash commands: …`，失敗是 `[commands] slash command registration failed: …`（status 的「最近的錯誤」會列出）。
- `contexts`：`/clear`、`/resume` 只在和 Bot 的私訊（BotDM）；其他是伺服器（含討論串）＋私訊。`integration_types` 是 guild install。
- **scope**：依 Discord 官方文件，`applications.commands` 會隨 `bot` scope 自動包含；create-bot 的邀請網址也一直帶 `bot applications.commands`。已在伺服器的 Bot 不用重邀；選單真的沒出現時，用 `invite` 網址重新邀請一次，**重新邀請不會把 Bot 踢出伺服器**。
- **生效時間**：Discord 官方文件說 guild commands 即時生效，global commands 沒有寫確切時間（有 read-repair：過期的指令在使用時會被拒絕並重新載入）。實務上通常幾分鐘內出現；看不到時重開 Discord 用戶端（電腦版 Ctrl+R）。
- **多隻 Bot 在同一個伺服器**：每隻 Bot 都註冊同名指令，Discord 選單依 App 分組；互動只會送給被選的那隻 Bot（程式也會再比對 application ID）。請成員從選單選對 Bot。
- **行為和權限與 `!` 指令完全一致**：兩者轉成同一個 Command，經過同一個 gate（鎖定 → 綁定頻道 → 白名單 → 討論串 → 私訊限定 → 主人或提出需求的人；私訊：只限主人 → 私訊開啟 → PIN 已設定 → PIN 已解鎖），再由同一個 `runCommand` 執行。差別只在回覆方式：互動先 defer（ephemeral），拒絕原因、`/help`、`/status`、選單都是 ephemeral；會改變對話的指令（`/model`、`/plan`、`/stop`、`/clear`、`/compact`、`/retry`、`/skill`）在對話裡公開留一則簡短紀錄。`!` 指令在鎖定、未綁定、不在白名單時一樣不回應（避免洗版），斜線指令則回 ephemeral 說明（互動不能不回）。私訊還沒解鎖時，斜線指令回一個「解鎖」按鈕，解鎖後再用一次（`!` 訊息會保留、解鎖後接著處理）。
- `!` 指令保留，當備用。

### /skill

- `/skill name:<名稱> [args:<參數>]`，或 `!skill <名稱> [參數]`（`!skill` 不帶名稱會列出清單）。把「`/名稱 參數`」當成使用者訊息送進該對話的 session，由 Claude Code 執行那個 skill 或自訂指令。
- 清單：session 啟動（init）後用 SDK 的 `supportedCommands()` 取得，`commands_changed` 時更新；以工作資料夾為 key 存在 `state.json` 的 `skills`。只列 skill（init 的 `skills`，含 Claude Code 內建的 bundled skill）和自訂指令（沒有 `builtin` 標記的），排除 Claude Code 內建指令和 `terminal_slash_commands`。`/compact` 是 SDK 裡確定可用的內建指令，用 channelcollab 自己的 `/compact`。
- 名稱只接受清單裡的、符合 `^[A-Za-z0-9][A-Za-z0-9_.:-]*$` 的名稱；參數合併成一行、最多 1500 字。
- 權限：和一般觸發一樣（白名單、主人或提出需求的人）。skill 執行時的工具一樣經過 PreToolUse hook：權限按鈕、PIN、禁區，**不會因為是 skill 就放行**（非 auto 模式下 hook 對每個工具呼叫都給明確的 allow／ask／deny，skill 的 `allowed-tools` 不會繞過）。
