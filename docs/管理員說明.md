# channelcollab 管理員說明

管理員負責：幫每位成員建 Discord Bot、把 token 安全地交給本人、發佈與更新 plugin。名冊由每個人自己維護（第 4 節）。

成員端的操作見 `docs/企劃使用說明.md`。

---

## 1. 整體流程

```
管理員                                         成員
 /channelcollab:create-bot（幫成員建）
   → 建 Bot、存 token 成交付檔
   → 驗證設定、邀請 Bot 進伺服器
   → 把新 Bot 寫進自己的名冊，主人 ID 附進交付檔
 私下把交付檔交給成員 ──────────────────────→  /channelcollab:setup
                                                → 匯入交付檔（token、主人 ID）
                                                → 刪除交付檔
                                                → 綁頻道、啟動
 每個人自己維護名冊 ────────────────────────→  /channelcollab:roster
                                                （把常合作的人和 Bot 加進來，只要 Discord ID）
```

---

## 2. 建 Bot：`/channelcollab:create-bot`

在自己的 Claude Code 執行 `/channelcollab:create-bot`，選「管理員幫某位成員建」。skill 會帶你在 Developer Portal 完成建立（可以用瀏覽器自動化，也可以一步步手動），重點：

- Bot 建在 Developer Portal 的 **Team** 底下，方便日後統一管理。
- token 只經過剪貼簿，由腳本存檔；**token 不會出現在對話裡**。
- 幫成員建時，token 存成**交付檔** `<HOME>\handoff\<成員名稱>-bot.json`，不會寫進你自己的 `config.json`。
- 交付檔建立時帶 `--owner-id <成員的 Discord 使用者 ID>`，成員匯入後自動成為 Bot 的主人（只有主人能按權限按鈕）。
- 最後寫名冊時帶 `--handoff "<交付檔>"`：新 Bot 寫進**你自己的**名冊，主人 ID 和這個 Bot 自己那一筆附進交付檔（成員的 Bot 因此知道自己是誰）。你的整份名冊不會附進去。

`<HOME>` 是管理員自己的 channelcollab 資料夾，預設 `%USERPROFILE%\.channelcollab`（環境變數 `CHANNELCOLLAB_HOME` 可以改）。

---

## 3. 安全地交付交付檔

**交付檔裡是明文 Bot token。** 拿到 token 的人可以用這個 Bot 的身分在伺服器上發言、讀取它看得到的訊息。

- 只用**私下管道**交給本人：Discord 私訊、公司內部的一對一訊息、當面用隨身碟。**不要貼在任何頻道、群組、共用資料夾或文件裡**。
- 成員匯入後，請對方刪除檔案，用私訊傳的也刪掉那則訊息；**你自己這邊的 `handoff\` 檔案也刪掉**。
- 懷疑外流時：到 Developer Portal 該 Bot 的 **Bot** 頁籤按 **Reset Token**，舊 token 立刻失效。再用 create-bot 的 `save-token --for member` 重產交付檔交給本人。

## 4. 名冊（每個人自己維護）

名冊決定一個 Bot 認得哪些 Bot、哪些人。有兩種條目：**Bot**（ID、名稱，可選填主人與角色）和**成員** `members`（人的 ID、名字，可選填角色）。Bot 用它在提示詞中標示發話者，知道要交棒給某個 Bot、或要找某個人（例如企劃）時該 @ 誰。

- **名冊是每個人自己的**：每個 Bot 只讀自己 HOME 的 `<HOME>\roster.json`，沒有「正本」，管理員也不用發放。管理員的名冊就只是管理員自己 Bot 的名冊。
- 建 Bot 時，create-bot 的 `roster` 子命令把新 Bot 寫進**建立者自己的**名冊。其他人想讓自己的 Bot 認得這個新 Bot，就用 `/channelcollab:roster` 自己加。
- 加入只要 Discord ID，名字和是不是 Bot 會用自己 Bot 的 token 向 Discord 查（伺服器暱稱優先）：
  ```
  node "<plugin>/scripts/channelcollab.mjs" roster add <Discord ID> [--role planner] [--home <HOME>]
  node "<plugin>/scripts/channelcollab.mjs" roster remove <Discord ID>
  node "<plugin>/scripts/channelcollab.mjs" roster list
  ```
  查不到時（沒有 token、ID 不存在）會要求 `--name <名字>`，Bot 再加 `--bot`。
- 想一次給別人很多條目，可以把自己的 `roster.json` 傳給對方（名冊沒有 token），對方用 `roster import <檔案>` **合併**：新的 ID 加進來，同一個 ID 預設保留對方自己的（加 `--theirs` 才改用你的）。
- 改了名冊從下一個新對話開始生效，不用重啟 Bot。Bot 啟動時 log 會印 `[roster] N bots, M members from <路徑>`。
- **名冊不放在 plugin 或 repo 裡**（repo 是公開的，名冊有真實的 Discord ID）。plugin 只附假資料的 `roster.example.json` 當格式範例。

格式：

```json
{
  "version": 1,
  "bots": [
    {
      "botId": "Bot 的使用者 ID",
      "botName": "Bot 顯示名稱",
      "ownerName": "主人名稱（可省略）",
      "ownerDiscordId": "主人的 Discord 使用者 ID（可省略）",
      "role": "engineer 或 planner（可省略）"
    }
  ],
  "members": [
    {
      "discordId": "人的 Discord 使用者 ID",
      "name": "名字",
      "role": "engineer 或 planner（可省略）"
    }
  ]
}
```

`members` 可以省略（舊的名冊沒有這個欄位，照常運作）。

## 5. 發佈與更新 plugin

### marketplace 位置

plugin 透過 GitHub repo `jijia-Huang/channelcollab` 發佈。repo 根目錄的 `.claude-plugin/marketplace.json` 宣告了一個 plugin，原始碼在 `plugin/` 子資料夾。成員安裝：

```
claude plugin marketplace add jijia-Huang/channelcollab
claude plugin install channelcollab@channelcollab
```

測試時也可以用本機資料夾當 marketplace：`claude plugin marketplace add <repo 的本機路徑>`（本機路徑的 marketplace 直接讀資料夾裡的檔案，改了重開 Claude Code 就生效）。

### 發佈新版

1. 改好 `src/` 之後，在 repo 根目錄執行：
   ```
   npm install
   npm run build:plugin
   npm run test:plugin
   ```
   `build:plugin` 會把 `src/` 打包成 `plugin/runtime/bot.mjs`、`stop.mjs`，並產生釘死版本的 `package.json`、`package-lock.json`、`version.json`。**這些產物要提交進 repo**：成員從 git 安裝時拿到的就是這些檔案，不會在他們電腦上建置。
2. **把 `plugin/.claude-plugin/plugin.json` 的 `version` 加一**（例如 0.1.0 → 0.1.1），再跑一次 `npm run build:plugin`。Claude Code 用這個版本號判斷有沒有更新；**沒改版本號，成員就收不到更新**。
3. 提交並推送。
4. 通知成員更新：
   ```
   claude plugin marketplace update channelcollab
   claude plugin update channelcollab@channelcollab
   ```
   重開 Claude Code 後 `/channelcollab:stop`、`/channelcollab:start`，start 會偵測到執行環境有新版並自動重新安裝。

### 執行環境放在哪裡

plugin 的安裝資料夾每次更新都會換一個新的，舊的過一陣子會被清掉，所以 Bot 的執行環境不放在那裡：setup 把 `plugin/runtime/` 複製到成員的 `<HOME>\runtime\`，在那裡用 `npm ci --omit=dev` 裝固定版本的依賴（約 300 MB，主要是 Agent SDK 內建的 Claude Code 執行檔）。桌面的啟動／停止 `.bat` 也指向這份複本，plugin 更新不會讓它失效。

---

## 6. 一台電腦跑多個 Bot

每個 Bot 用一個自己的 HOME 資料夾。所有指令都可以加 `--home "<資料夾>"`，或先設環境變數 `CHANNELCOLLAB_HOME`。匯入交付檔時，如果目標 HOME 已經有另一個 Bot 的 token，腳本會停下來，不會覆蓋（確定要取代才加 `--replace`）。

---

## 7. 疑難排解

| 狀況 | 處理 |
|---|---|
| 成員啟動時 401 | token 被 Reset 過或交付檔太舊。重產交付檔 |
| Bot 上線但收不到訊息內容 | Message Content Intent 沒開。用 create-bot 的 `verify` 檢查 |
| 成員說權限按鈕按了沒反應 | 確認按的人是主人：`/channelcollab:status` 看主人 ID 是否正確，不對就 `set-owner` |
| 成員的 Bot 不認得某個新 Bot 或某個人 | 那個 Bot／人不在對方的名冊裡。請對方 `/channelcollab:roster` 用 Discord ID 加進去 |
| 更新 plugin 後行為沒變 | 檢查是否改了 `plugin.json` 的 `version`；成員要 stop 再 start 才會換新的執行環境 |
