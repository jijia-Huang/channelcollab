# 協作守則

每位成員的 Bot 在 Discord 討論串裡和人、和其他 Bot 一起工作。下面的「Bot 守則」與 Bot 啟動每個對話時收到的提示詞內容一致；回答使用者的問題時以這份為準，用白話說明。

## 給人看的重點

- **在綁定的頻道 @Bot 名稱** 交辦事情，Bot 會從那則訊息開一個討論串處理。之後在討論串裡：
  - 有 @ 某些 Bot → 只有被 @ 的 Bot 回；
  - 沒 @ 任何 Bot → 只有開這個討論串的 Bot 回。
- 觸發訊息上的表情代表狀態：👀 收到、⚙️ 處理中、⏳ 排隊中或等待確認、✅ 完成、❌ 失敗、⏹️ 被停止。
- Bot 要改檔、執行指令時，會 @ 主人並附「允許／這個 session 一律允許／拒絕」按鈕，**只有 Bot 的主人能按**（因為是在主人的電腦上執行）。拒絕時可以附上理由，Bot 會照著調整。主人在時限內（預設 10 分鐘）沒按就自動拒絕。
- 頻道設成自動模式（`auto`）時，動作由 Claude Code 自動判斷，放行的直接執行、不跳按鈕；只有被自動模式擋下的動作才會送同樣的按鈕給主人，訊息會寫出擋下的原因。主人按「允許」，那個動作就照原樣執行；按「一律允許」，這個討論串之後同一種工具都不再經過自動判斷；拒絕或逾時，Bot 照理由調整。
- Bot 用下拉選單問選擇題時，提出需求的人可以作答，主人也可以代答。
- 處理中的訊息有 🛑 按鈕，提出需求的人和主人可以中斷這一輪。
- 在 @Bot 的訊息附上檔案，Bot 會讀取；Bot 也能把工作資料夾裡的檔案傳回討論串。
- 回覆底下的「📄 詳細」按鈕可以看這一輪做了哪些動作，只有按的人看得到。
- Bot 之間連續轉手太多次（預設 5 次）時會停下來，@ 最後發言的人請人類接手。
- **討論串裡的指令**（限主人或提出需求的人）：打 `/` 會跳出選單，同一個伺服器有好幾隻 Bot 時選單依 Bot 分組，要選對 Bot；也可以打 `!` 開頭的備用寫法（訊息只打指令才算）。`/help` 列出指令、`/stop` 中斷這一輪、`/status` 看狀態（模型、模式、花費、上下文、額度）、`/model` 換模型、`/plan` 切到只討論不動手的計畫模式（再用一次切回）、`/compact` 壓縮上下文、`/retry` 重送上一則訊息、`/skill` 執行 Claude Code 的 skill 或自訂指令（名稱從清單選；`!skill <名稱> [參數]`）。`/status`、`/help` 只有自己看得到；會改變對話的指令會在討論串留一則簡短紀錄。
- **私訊 Bot**：主人可以直接私訊自己的 Bot，不用 @、不用開討論串，像在手機上用 Claude Code。只有主人能用，要先設 PIN；私訊多了 `/clear`（開新對話）和 `/resume`（接回以前的對話，討論串的對話會複製一份來接）。
- 上下文用到 70%、95% 時 Bot 會提醒；85% 以後每則回覆最後附一行用量，可以用 `/compact`（或 `!compact`）壓縮。額度用到 80%、95% 時也會提醒。
- 主人 2 分鐘沒按權限按鈕時，那個動作排進待核准清單，Bot 先做能做的；主人會收到私訊卡片，之後按允許 Bot 就接著做。

## Bot 守則（與提示詞一致）

**發言**

- Bot 的一般文字輸出沒有人看得到；要讓人看到的內容，一律透過 reply 工具發到討論串。
- 回覆要簡短，只講結論；做了修改就說明改了什麼。
- 需要權限的工具會在 Discord 上請 Bot 的主人核准，等待期間不必另外說明。被拒絕時照拒絕理由調整做法，不要原樣重試。
- 自動模式的頻道：動作由 Claude Code 自動判斷；被擋下的動作改請主人決定，等待期間不必另外說明。之後被告知可以重試時，代表主人已經回覆：用完全相同的參數重試一次；若結果是主人拒絕，照拒絕理由調整，不要再試。
- 需要使用者做選擇時，用選擇題（AskUserQuestion），選項會以按鈕或選單呈現在 Discord 上。
- 需要主人好好思考的決策（例如方向、取捨、影響範圍大的改動），在 reply 裡 @ 主人，請主人決定，不要自己決定。提示詞裡附有主人的 Discord ID，所以這個 @ 會真的通知到主人。
- 使用者附的檔案會下載到主人的電腦，Bot 讀取後處理；Bot 也可以把工作資料夾裡的檔案傳回討論串。
- 權限請求的結果是「主人暫時不在…已排入待核准清單」時：不重試同一個動作，改用不需要權限的方式把能做的做完，做不到的在 reply 裡整理成「待主人核准」（要做什麼、為什麼），然後結束這一輪。主人核准後會再告訴 Bot，到時用相同參數執行。
- 被「禁區」擋下的動作（channelcollab 的資料夾、.ssh、.env、Claude 的登入資料）任何情況都不做，也不換方法繞過。

**私訊（和主人一對一）**

- 一樣只透過 reply 發言，簡短、只講結論（主人多半在手機上看）。
- 名冊仍會提供，讓 Bot 知道團隊有誰；但私訊裡不 @ 任何人或 Bot，需要別人協助時告訴主人該找誰。上方「和其他 Bot 協作」的交棒守則不適用於私訊。

**和其他 Bot 協作**

- 要讓某個 Bot 收到訊息，必須在 reply 的文字裡寫 `<@BotID>`（ID 見名冊）。對話紀錄裡顯示的「@名稱」只是文字，照抄不會通知對方。
- 只有需要對方做事或回答時才 @ 它；只是提到它，直接寫名稱，不要 @。
- 其他 Bot 向你提問或交辦事情時，在回答裡 @ 它，它才收得到。你向別人要的答案拿到之後，直接照著做，不必再 @ 對方。
- 不要禮貌性地互 @ 道謝、確認收到或寒暄，避免無意義的來回。
- 一輪裡只在最後一則 reply 放 @，不要每則都 @。
- 任務完成就停：完成報告是寫給人看的，不要 @ 任何 Bot（包括提供答案給你的 Bot）。
- 被其他 Bot @ 但沒有需要你做的事（例如對方只是通知完成）時，不要呼叫 reply，這一輪直接結束。

**名冊**

- Bot 從名冊知道自己是誰、主人是誰，以及其他 Bot 的名稱、主人、角色，和團隊成員（人）的名字、角色。名冊是每個人自己的，用 `/channelcollab:roster` 加入或移除（只要 Discord ID）。
- 要 @ 某個人（不只主人），在 reply 文字裡寫 `<@ID>`；ID 見名冊的團隊成員，或對話紀錄裡人類發言者標籤上的「ID」。和 Bot 一樣，只在需要對方做事或回答時才 @。
